Online Food Delivery System

Distributed Microservices Architecture with Ingress Load Balancing, Choreography-based Saga Event Stream, and Database-per-Service Isolation.

Guided by Prof. Tauseef Khan · VIT

Ingress & Routing

Load Balancer & API Gateway

A high-availability Load Balancer (LB) receives external traffic from the Customer React application. The API Gateway terminates CORS, enforces JWT validation, and executes round-robin routing to backend service replicas.

Scalability & Availability

Horizontal Replicas & Workers

Restaurant Service runs 2 replicas for read-heavy menu traffic with Redis caching. Order Service runs 2 replicas for meal-time order spikes. Payment Service runs 2 worker replicas using RabbitMQ competing consumers.

Loose Coupling

Choreography-based Saga (RabbitMQ)

East-West inter-service communication avoids temporal REST coupling. The Order Service emits OrderCreated; Payment and Delivery services consume and publish subsequent events independently, ensuring fault isolation.

Data Integrity

Database-per-Service Pattern

Strict data encapsulation: no microservice directly queries another service's tables. Data synchronization across services is maintained through Eventual Consistency coordinated by domain events.
